# 送货单OCR识别与Excel导出系统 - 设计文档

**日期：** 2026-07-24
**状态：** 已确认

---

## 1. 概述

构建一个内网Web应用，用户上传送货单PDF（扫描件）或图片，通过PaddleOCR识别文字，解析出表格数据，在网页上预览并修正，最后导出为Excel文件。

## 2. 约束条件

- 部署环境：Windows 本机/内网
- 用户：单用户，无需登录
- 送货单格式：固定格式（表头和数据行位置一致）
- PDF类型：扫描/图片型PDF

## 3. 技术栈

| 组件 | 选型 | 理由 |
|---|---|---|
| Web框架 | Flask | 轻量，单用户场景最优 |
| PDF转图片 | PyMuPDF (fitz) | 纯Python，无需安装poppler |
| OCR引擎 | PaddleOCR (ONNX) | 已安装验证通过，中文识别效果好 |
| Excel导出 | openpyxl | Python标准Excel库 |
| 前端 | HTML + Bootstrap 5 + 原生JS | 简单够用，无需Node.js构建工具 |
| 前端表格编辑 | Tabulator 或 原生table | 可编辑表格，支持修正 |

## 4. 处理流程

```
上传文件 → 类型检测 → PDF转图片 → PaddleOCR识别 → 表格结构解析 → 网页预览+人工修正 → 导出Excel
```

### 4.1 上传
- 支持 PDF、PNG、JPG、JPEG 格式
- 文件存入 `uploads/` 目录

### 4.2 PDF转图片
- 使用 PyMuPDF 将PDF每页渲染为高分辨率PNG
- 支持多页PDF，每页独立OCR处理

### 4.3 OCR识别
- 使用现有PaddleOCR（ONNX引擎、中文模型）
- 输出包含文字内容和坐标信息

### 4.4 表格解析（核心）
OCR输出的坐标信息用于重建表格结构：
- **Y坐标聚类** — 按垂直位置将文字分入不同的"行"
- **X坐标排序** — 每行内按水平位置确定列顺序
- **表头匹配** — 识别表头行（包含"名称""单位""单价"等关键词），确定每列含义
- **数据映射** — 将数据行文字按列映射到对应字段
- **序号列处理** — 自动生成序号（如OCR未识别出来）

### 4.5 网页预览修正
- 以可编辑表格展示解析结果
- 支持单元格编辑、行删除、行添加
- 显示原始图片供对照
- 确认后导出Excel

### 4.6 Excel导出
- 固定表头：序号、名称、单位、购定价（含税）、税率、网上询价、数量、合计、备注
- 格式化输出，数字列保留合适小数位

## 6. 表格解析算法详细设计

### 6.1 行分组
- 收集所有OCR文字块及其Y坐标（使用多边形中心点或顶部Y值）
- 设定Y坐标容差（如10-15像素），将Y坐标相近的文字归为同一行
- 按Y坐标升序排列各行

### 6.2 列分组
- 对每行内的文字按X坐标排序
- 通过分析多行的X坐标分布，确定列边界

### 6.3 表头识别
- 扫描前几行，查找包含关键词的文字：
  - "名称" / "品名" / "商品名称" → 名称列
  - "单位" → 单位列
  - "单价" / "购定价" / "含税" → 购定价列
  - "税率" → 税率列
  - "询价" / "网上询价" → 网上询价列
  - "数量" → 数量列
  - "合计" / "金额" → 合计列
  - "备注" → 备注列
- 序号列如果存在，通常在第一列

### 6.4 数据行提取
- 表头行之后的行为数据行
- 过滤空行、合计行（通常包含"合计""总"等关键词）
- 每行按列映射提取对应文字

## 7. 错误处理

- 文件格式不支持 → 前端提示
- PDF损坏/无法读取 → 返回错误信息
- OCR识别为空 → 提示用户检查图片质量
- 表头匹配失败 → 降级为原始文字列表展示
- 表格解析异常 → 保留原始识别结果供用户手动整理
